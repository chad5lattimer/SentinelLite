- The coverage report's one remaining named gap was `core/filesystem.py`
  (90%, missing lines 53 and 116-118): the `os.walk(..., onerror=...)`
  callback that logs "Cannot list directory" (section 8's "a permission
  error must not terminate the scan") and the `except OSError` branch
  around per-file `stat()`/hashing. Both are real, reachable error paths,
  but the only test exercising them
  (`test_scan_directory_continues_after_permission_error`) uses a real
  `chmod(0)` and correctly `pytest.skip()`s when running as root — which
  is how this container (and, per the status history, every prior CI run)
  executes. This is the exact same root cause Runs 10-12 already found
  and fixed in `storage/`, `gui/dialogs.py`, `gui/main_window.py` /
  `results_view.py`, and `core/baseline.py`.
- Closed it with 2 new tests in `tests/test_filesystem.py`, using the same
  "monkeypatch the seam directly" technique as those prior runs rather
  than relying on real permission enforcement:
  - `test_scan_directory_logs_warning_when_directory_cannot_be_listed`
    monkeypatches `os.walk` to invoke the real `onerror` callback with a
    simulated `OSError`, then asserts the warning is logged and
    enumeration continues for the rest of the directory.
  - `test_scan_directory_records_error_when_hashing_raises_oserror`
    monkeypatches `core.filesystem.calculate_sha256` to raise `OSError`
    for one specific file, then asserts that file surfaces as a
    `FileError` while the other file is still recorded normally.
  Both patch at the same production seams `scan_directory` already calls
  through (`os.walk`, `calculate_sha256`) — no new indirection or
  test-only hooks were added to production code, and no production
  behavior changed.
- Re-ran the full suite after the change:
  - Headless (Python 3.11, no `tkinter`): **58 passed, 31 skipped** (+2
    passed from the two new tests, which need no display; 0 new
    failures).
  - Real display (`xvfb-run`, Python 3.12 + `customtkinter` + `tkinter`,
    with coverage): **95 passed, 4 skipped** (93 + 2 new passes, 0 new

    run — the chmod-based permission tests in `test_hasher.py`,
    `test_scanner.py`, `test_baseline.py`, and `test_filesystem.py`,
    which correctly skip under root since `chmod(0)` doesn't block reads

  - Coverage: `core/filesystem.py` is now at **100%** line coverage.
