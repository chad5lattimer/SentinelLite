## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time —
  section 6.1) and `FileAccessError` (path, message) dataclasses.
- `core/hasher.py`: `calculate_sha256()` — incremental, chunked SHA-256
  hashing via `hashlib` (default 1 MiB chunks from
  `config.DEFAULT_HASH_CHUNK_SIZE`, section 7.2). Never loads a full file
  into memory. Lets `OSError` subclasses propagate for the caller to turn
  into recorded errors.
- `core/filesystem.py`:
  - `iter_files()` — recursive directory walk (`os.walk`) yielding every
    regular file. Skips symbolic links (files and directories) by
    default; see "Notes / decisions" below for the section 8.2 symlink
    policy. Directories that can't be listed are logged and skipped
    (`onerror` callback) instead of aborting the walk (section 8.3).
  - `build_file_records()` — enumerates + hashes a directory, returning
    `(list[FileRecord], list[FileAccessError])`. Per-file read failures
    are caught, logged, and recorded as `FileAccessError` without
    stopping the rest of the scan (section 7.3).
  - Paths are stored relative to the scanned root, normalized to forward
    slashes, per section 6.2.
- `tests/test_hasher.py`: same-file/modified-file/empty-file/large
  (chunked, cross-checked against `hashlib` directly)/missing-file/
  invalid-chunk-size cases (section 19 "Hashing" minimum coverage).
- `tests/test_filesystem.py`: recursive enumeration with nested
  directories, relative forward-slash paths, correct hash/size/mtime,
  empty directory, nonexistent root, unreadable file (scan continues,
  error recorded), and symlinked file/directory skipped by default. Not
  one of the file names listed in section 5's example test layout, but a
  direct, minimal counterpart to the new `core/filesystem.py` module.

## Notes / decisions

- **Symlink policy (section 8.2):** symbolic links are not followed by
  default -- symlinked files are skipped and symlinked directories are
  pruned before `os.walk` descends into them. Rationale: following links
  risks infinite loops (a link back into an ancestor directory) and could
  silently pull files from outside the monitored directory into the
  baseline, which is a surprising trust boundary for an integrity tool.
  `iter_files(..., follow_symlinks=True)` is available for a future,
  explicitly-opted-in use case, but is not exposed anywhere yet.
  Documented per the spec's requirement to record this choice.
  Windows note: this decision applies equally to Windows reparse
  points/junctions once the app runs there — `Path.is_symlink()` reports
  them as such, so the same pruning logic applies without change.
- Kept `core/filesystem.py` free of any baseline/scan-comparison logic;
  that belongs to `core/baseline.py` (Run 3) and `core/scanner.py`
  (Run 4), which will consume `FileRecord`/`FileAccessError` from this
  module.
- No changes to `config.py`, `app.py`, or `gui/` this run -- Run 2 is
  scoped to the core engine only, per section 27's "No GUI integration is
  required beyond basic scaffolding."
