## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) and
  `FileError` (path, message) frozen dataclasses per spec section 6.1.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, sourced from `config.DEFAULT_HASH_CHUNK_SIZE`)
  so large files are never fully loaded into memory (section 7.2). Raises
  `OSError` on unreadable files; does not swallow errors itself.
- `core/filesystem.py`:
  - `enumerate_files()` -- recursive directory walk (`os.walk`,
    `followlinks=False`) yielding every regular file. Symbolic links to
    files or directories are skipped entirely and documented as
    intentional (section 8.2), avoiding symlink-cycle loops and hashing
    content outside the monitored tree. Directory listing errors are
    logged and the walk continues rather than aborting (section 8.3).
  - `scan_directory()` -- enumerates and hashes every file under a root,
    returning `(list[FileRecord], list[FileError])`. Per-file read/hash
    failures are caught, logged, and recorded as `FileError` instead of
    crashing the scan (section 7.3). Paths are relative to the root and
    POSIX-style (forward slashes) for baseline portability (section 6.2).
- `tests/test_hasher.py`: same-file/identical-content hashing, modified
  file produces a different hash, empty file hashing, large file
  (5 MiB) hashing with a small chunk size to exercise the chunked read
  path, agreement with `hashlib` as a reference, missing-file and
  invalid-chunk-size error handling.
- `tests/test_filesystem.py`: recursive enumeration matches the
  directory tree from spec section 8's example, `FileRecord` production
  and field correctness, empty-directory handling, an unreadable file
  and an unreadable directory are skipped without aborting the scan
  (POSIX-only, skipped when running as root), and both a symlinked file
  and a symlinked directory are confirmed *not* to be followed
  (POSIX-only).

## Notes / decisions

- Symbolic links are never followed (files or directories) rather than
  being made configurable -- the spec permits either choice as long as
  it is documented (section 8.2); "never follow" is the simpler and
  safer default and keeps this run's scope minimal.
- `scan_directory()` lives in `core/filesystem.py` rather than a
  separate module, since spec section 27 assigns hashing +
  enumeration + metadata collection to `core/hasher.py` and
  `core/filesystem.py` jointly, and `core/models.py` stays free of any
  filesystem or hashing logic.
- Chunk size remains configurable via `calculate_sha256(..., chunk_size=...)`
  and `scan_directory(..., chunk_size=...)`, defaulting to
  `config.DEFAULT_HASH_CHUNK_SIZE` (1 MiB), per section 7.2.
- No database or baseline logic was added; `scan_directory()` returns
  plain in-memory data structures for the baseline/scanner components
  (Runs 3-4) to consume.
