## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) per
  spec section 6.1, plus `FileAccessError` (path, message) used to report
  unreadable files without raising.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable) per spec section 7.2. Never
  loads a full file into memory.
- `core/filesystem.py`:
  - `enumerate_files()` -- recursively walks a directory via `os.walk`,
    yielding every regular file. Symbolic links (files and directories)
    are deliberately **not followed** (documented in the module
    docstring per spec section 8.2), to avoid symlink cycles and
    ambiguous baseline paths. Directories that raise a permission error
    while being listed are logged and skipped (spec section 8.3) rather
    than aborting the walk.
  - `collect_file_records()` -- hashes every enumerated file and returns
    `(records, errors)`; a file that cannot be opened/read is logged and
    added to `errors` instead of raising, so the rest of the directory
    continues to be processed (spec section 7.3).
- `tests/test_hasher.py` (8 tests): identical files hash identically, a
  modified file hashes differently, empty-file hashing, large multi-chunk
  file hashing (chunk-size independence verified), a known-vector check
  against `hashlib` directly, and error behavior for an invalid chunk size
  / missing file.
- `tests/test_filesystem.py` (8 tests): recursive enumeration matches the
  section-8 example tree shape, `FileRecord` fields are correct
  (hash/size/mtime), relative paths use forward slashes, empty
  directories, symlinked files/directories are skipped and not followed,
  and (skipped when running as root, since permission bits are bypassed)
  an unreadable file/directory is reported via `FileAccessError` rather
  than raising.
- `PROJECT_SPEC.md` / `SentinelLite.md` / `README.md`: progress line and
  status updated to reflect Run 2 completion.

## Notes / decisions

- Symbolic-link handling: per spec section 8.2 ("avoid recursively
  following symbolic links unless explicitly determined to be safe...
  document the chosen behavior"), SentinelLite skips symlinks entirely
  (files and directories). This is the simplest, safest option and is
  documented in `core/filesystem.py`'s module docstring.
- `core.filesystem` depends on `core.hasher` and `core.models` only (plus
  `config` for the default chunk size) -- no dependency on `storage` or
  `gui`, preserving the layered architecture from spec section 5.
- `FileAccessError` was added to `core/models.py` now (rather than
  deferring it) since `collect_file_records()` needs a typed way to report
  per-file errors without raising; this is a small, spec-consistent
  addition (section 7.3 explicitly requires recording read errors) and
  will be reused by the scanner in Run 4 for `ERROR`-status results.
