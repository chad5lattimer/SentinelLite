## Completed this run

- `core/models.py`: `FileRecord` dataclass (path, sha256, size,
  modified_time), `ScanStatus` enum (NEW/MODIFIED/DELETED/UNCHANGED/ERROR)
  for the future scan engine, and `FileError` for unreadable files.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable via
  `config.DEFAULT_HASH_CHUNK_SIZE` or a per-call override). Raises
  `OSError` on unreadable files rather than swallowing the error; callers
  decide how to handle it.
- `core/filesystem.py`: `scan_directory()` -- recursively enumerates a
  directory with `os.walk`, hashes every regular file, and returns
  `(records, errors)`. Permission errors and other per-file read failures
  are caught, logged, and recorded as `FileError` entries without stopping
  the scan (spec sections 7.3 / 8.3). Supports an optional progress
  callback for future GUI wiring (section 13). Relative paths are stored
  with forward slashes for baseline portability.
- **Symbolic link decision (spec section 8.2):** symlinks are not
  followed, for both directories and individual files. This avoids
  infinite recursion on cyclic links and prevents files from outside the
  monitored root from silently entering the baseline. Documented in
  `core/filesystem.py`'s module docstring.
- `tests/test_hasher.py`: same-file/modified-file/empty-file/large-file
  hashing, chunk-size independence, and unreadable/missing file handling.
- `tests/test_filesystem.py`: nested enumeration, correct `FileRecord`
  fields, forward-slash relative paths, continuing past a permission
  error, symlinked directories and files not followed, progress callback
  invocation, and rejecting a non-directory path.
- Updated `PROJECT_SPEC.md` progress line and `README.md` status banner.
