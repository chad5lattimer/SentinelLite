# SentinelLite — Status Report

## Summary

Implements PROJECT_SPEC.md section 27 (Run 2): the core hashing and
filesystem enumeration engine. Builds on Run 1's foundation
(`app.py`, `config.py`, logging, GUI shell) without modifying it.
No GUI wiring is included -- that is scoped to Run 5.

## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time per
  spec section 6.1) and `FileError` (path, message) as frozen
  dataclasses. Baseline/scan-result models (section 6.2/6.3) are
  deferred to Runs 3-4, when they are actually used.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, via `config.DEFAULT_HASH_CHUNK_SIZE`)
  so large files never load fully into memory (spec section 7.2).
  Unreadable files raise `HashError` rather than an uncaught `OSError`,
  so callers can record an ERROR result instead of crashing (section
  7.3).
- `core/filesystem.py`:
  - `iter_files()` -- recursive directory walk (`os.walk`) that yields
    every regular file under a root, skips directories it cannot list
    (permission errors; logged via `onerror`, not fatal -- section
    8.3), and does not follow symbolic links for either directories or
    files (section 8.2). The symlink decision is documented in the
    module docstring: symlinked dirs are pruned before descent, and
    symlinked files are skipped, since a link's target may point
    outside the monitored directory.
  - `build_file_record()` -- stats + hashes one file into a
    `FileRecord`, using a forward-slash relative path regardless of
    platform.
  - `scan_directory()` -- enumerates and hashes every file under a
    root, returning a `ScanOutcome(records, errors)`; a file that
    cannot be read is captured as a `FileError` and the scan continues
    with the remaining files (sections 7.3, 8.3).
- `tests/test_hasher.py` (9 tests): same file -> same hash, modified
  file -> different hash, empty file, "large" file with a small chunk
  size (exercises multiple incremental reads), chunk-size independence,
  missing file, unreadable file (permission-denied, skipped when
  running as root), and invalid chunk size.
- `tests/test_filesystem.py` (9 tests): recursive enumeration matching
  the directory example in spec section 8, `FileRecord` production and
  correctness (hash/size/path), empty-directory handling, continuing
  after an unreadable file and an unreadable directory (skipped when
  running as root), and that symlinked files/directories are not
  followed.
- `PROJECT_SPEC.md` / `SentinelLite.md` / `README.md`: progress notes
  updated to reflect Run 2 completion.

## Notes / decisions

- Symbolic links (files and directories) are not followed. This is a
  deliberate, documented choice (see `core/filesystem.py` module
  docstring) rather than an oversight -- spec section 8.2 explicitly
  permits avoiding symlink traversal and asks that the decision be
  documented.
- `core/models.py` intentionally does not yet include baseline or
  scan-result structures (spec sections 6.2/6.3); adding them now
  would be speculative since Runs 3-4 define how they're actually
  used. Per spec section 38 (Scope Control Rule), they are deferred.
- Existing Run 1 code (`app.py`, `config.py`, `gui/main_window.py`) was
  reviewed and found functionally correct against the spec; it was not
  modified.
