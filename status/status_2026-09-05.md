## Summary

Implements PROJECT_SPEC.md section 27 (Run 2): recursive file enumeration,
chunked SHA-256 hashing, `FileRecord`/`FileError` models, and permission
error handling. No baseline, scan-comparison, or GUI-wiring logic is

## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) and
  `FileError` (path, message) frozen dataclasses, per section 6.1.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing via `hashlib`, using `config.DEFAULT_HASH_CHUNK_SIZE` (1 MiB) as
  the default chunk size, per section 7. Raises `OSError` on unreadable
  files rather than swallowing errors; enumeration is responsible for
  catching and continuing (section 7.3).
- `core/filesystem.py`: `enumerate_and_hash()` -- recursively walks a
  directory with `os.walk`, hashes every readable file, and returns an
  `EnumerationResult(records, errors)`. Directory-listing failures and
  per-file read failures are both captured as `FileError` entries and do
  not stop the walk (section 8.3). Relative paths use forward slashes on
  all platforms (section 6.2).
- Symbolic-link handling (section 8.2, decision recorded per the spec's
  request to document the chosen behavior): SentinelLite does **not**
  follow symbolic links. Symlinked files are skipped entirely; symlinked
  directories are not descended into. Neither produces a `FileRecord` or a
  `FileError` -- this avoids escaping the monitored root and avoids
  symlink cycles. This is a documented MVP limitation: a symlink's target
  is not independently monitored.
- `tests/test_hasher.py`: same file -> same hash, modified file -> different
  hash, empty file, large/multi-chunk file, hash is independent of chunk
  size, missing file raises `OSError`, invalid chunk size raises
  `ValueError`.
- `tests/test_filesystem.py`: empty directory, recursive enumeration across
  nested subdirectories, forward-slash relative paths, unreadable file is
  reported as a `FileError` while the scan continues (skipped when running
  as root, since root bypasses POSIX permission bits), symlinked file is
  skipped, symlinked directory is not followed, custom chunk size is
  honored end-to-end.

## Notes / decisions

- `enumerate_and_hash()` returns both successes and failures in one
  `EnumerationResult` (a `NamedTuple` of `records` and `errors`) rather
  than raising on the first failure or silently dropping failures --
  matching section 7.3 ("record an ERROR result... continue processing...
  inform the user after the scan") while leaving how failures become
  scan-result `ERROR` rows (with a `status`) to the scanner in Run 4.
- Kept `core/hasher.py` and `core/filesystem.py` free of any logging
  side effects beyond `logging.warning()` on a per-file/per-directory
  basis, so hashing remains directly unit-testable without touching the
  application's log configuration.
- Did not add a `core/baseline.py` or database code this run -- that is
  Run 3's scope per section 28.
