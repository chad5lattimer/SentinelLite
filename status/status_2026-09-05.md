## Summary

Implements PROJECT_SPEC.md section 27 (Run 2): the core hashing and

## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time),
  `FileAccessError` (path, message) for files that cannot be enumerated
  or hashed, and the `ScanStatus` enum (`NEW`/`MODIFIED`/`DELETED`/
  `UNCHANGED`/`ERROR`) from section 6, added now since `hasher`/
  `filesystem` and the section-28/29 baseline/scanner work will share it.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable, per section 7.2). Read
  failures raise `HashError` (an `OSError` subclass) rather than
  crashing, and are logged.
- `core/filesystem.py`: `iter_files()` recursively enumerates regular
  files under a root directory; `build_file_records()` hashes each file
  found and returns `(list[FileRecord], list[FileAccessError])`, using
  root-relative POSIX-style paths per section 6.2. Unreadable files and
  directories are skipped and recorded/logged rather than aborting the
  scan (sections 7.3, 8.3).
- **Symlink policy (section 8.2):** symbolic links -- to files or
  directories -- are not followed. This is documented in
  `core/filesystem.py`'s module docstring: it avoids link-cycle
  recursion and duplicate-path hashing, at the cost of not monitoring
  symlinked content. This can be revisited later if a concrete
  requirement emerges.
- `tests/test_hasher.py`: hashing tests (same file -> same hash, modified
  file -> different hash, empty file, large file with a deliberately
  small chunk size to exercise multiple reads, missing file ->
  `HashError`) and filesystem tests (recursive enumeration, `FileRecord`
  production with correct relative paths/sizes/hashes, symlinked files
  and directories skipped, and scan continuation past unreadable files/
  directories). Permission-based tests are skipped on Windows and when
  running as root (POSIX permission bits aren't enforced for root), since
  this environment runs the suite as root; they exercise real behavior on
  a normal user account or in CI.
