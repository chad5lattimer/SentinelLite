## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) and
  `FileError` (path, message) dataclasses, per `PROJECT_SPEC.md` section
  6.1. Paths are always relative to the monitored root and use forward
  slashes, so a baseline stays comparable across platforms.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing via `hashlib` (default chunk size: 1 MiB, from
  `config.DEFAULT_HASH_CHUNK_SIZE`). Never loads a full file into memory.
  Raises `OSError` on unreadable files so callers can turn that into a
  non-fatal per-file result (section 7.3).
- `core/filesystem.py`:
  - `enumerate_files()` -- recursive directory walk. Symbolic links
    (files or directories) are always skipped and logged, never followed
    -- documented decision per section 8.2, avoiding link cycles and
    walks outside the monitored root. A directory that cannot be listed,
    or an entry that cannot be `stat`-ed, is logged and skipped rather
    than aborting the walk (section 8.3).
  - `scan_directory()` -- combines enumeration + hashing + metadata
    collection into `(records, errors)`: a list of `FileRecord` for every
    readable file, and a list of `FileError` for anything that could not
    be read. One unreadable file never stops the rest of the scan.
- `tests/test_hasher.py` (7 tests): same file → same hash, modified file
  → different hash, empty file, large file with a small chunk size
  (verifies chunked reads against a one-shot `hashlib` digest of the same
  bytes), digest format, invalid chunk size, missing file.
- `tests/test_filesystem.py` (8 tests): recursive enumeration matching
  the section 8 example tree, `FileRecord` field correctness, relative
  POSIX-style paths, continuing past an unreadable file (simulated via
  monkeypatching rather than real OS permission bits, since the CI/dev
  container runs as root and would otherwise ignore `chmod`), symlinked
  files and symlinked directories both skipped, empty directory, and a
  missing root directory.

## Notes / decisions

- Symbolic links are skipped rather than followed (section 8.2); this is
  documented in `core/filesystem.py`'s module docstring as the spec
  requires.
- `FileError` was added to `core/models.py` alongside `FileRecord` (not
  explicitly named in section 6, but implied by sections 7.3/8.3's
  requirement to record rather than raise on unreadable files). This
  keeps error reporting a typed, reusable shape for the baseline/scanner
  layers in later runs, instead of ad hoc tuples.
- Permission-error tests use monkeypatching instead of `chmod`, because
  this development container runs as root, which bypasses Unix file
  permission bits -- a real `chmod 000` test would pass for the wrong
  reason (or not exercise the error path at all) in that environment.
  This does not change production behavior; `calculate_sha256` still
  raises `OSError` on a genuine permission error on Windows or as a
  non-root user.
