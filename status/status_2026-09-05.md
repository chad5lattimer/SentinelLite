## Summary

This run implements PROJECT_SPEC.md section 27 (Run 2): the core
hashing/filesystem engine. Run 1's foundation (app entry point, config,
logging, basic GUI shell) was verified intact and unchanged. No GUI
integration was added -- the engine is exercised entirely through the
`core` package and its tests, as scoped.

## Completed this run

- `core/models.py`: `FileRecord` and `FileAccessError` dataclasses
  (PROJECT_SPEC.md section 6.1/6.2), immutable and free of any
  filesystem/hashing logic.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable) using only `hashlib`.
  Never loads a whole file into memory; raises `OSError` for unreadable
  files so the caller can record a recoverable error (section 7.3).
- `core/filesystem.py`: `iter_files()` recursively walks a directory
  (`os.walk`) and `build_file_records()` hashes every discovered file,
  producing `FileRecord`s plus a list of `FileAccessError`s for files
  that could not be read. Directory listing errors (permission denied)
  are logged and skipped rather than aborting the walk (section 8.3).
- Symbolic links (section 8.2): documented decision -- symlinked files
  and directories are **not followed by default** (`follow_symlinks`
  defaults to `False`), preventing link cycles or the scan silently
  leaving the monitored tree. Opt-in following is available for future
  use but not exposed in the GUI.
- Paths in `FileRecord.path` are always relative to the monitored root
  and use forward slashes (`Path.as_posix()`), matching the baseline
  example in section 6.2 and keeping baselines portable across drives.
- `tests/test_hasher.py`: same file -> same hash, modified file ->
  different hash, empty file, large (multi-chunk) file, chunk-size
  independence, missing file raises, invalid chunk size rejected.
- `tests/test_filesystem.py`: nested-directory enumeration, relative
  path/hash/size/mtime correctness, empty directory, unreadable file is
  recorded as an error and the scan continues, symlinked file/directory
  not followed by default.

## Notes / decisions

- `core/filesystem.py` returns both successes and errors from a single
  `build_file_records()` call (`EnumerationResult`) rather than raising,
  so Run 3/4 can decide how to surface partial failures (e.g. baseline
  creation warnings, or `ERROR` scan rows) without re-walking the tree.
- Kept `DEFAULT_CHUNK_SIZE` defined in `core/hasher.py` (mirroring
  `config.DEFAULT_HASH_CHUNK_SIZE`) so `core/` has no import-time
  dependency on `config`; both currently agree on 1 MiB.
