A caught bug from this manual check (not from `pytest`, which already
drives the event loop correctly via `_pump_until`): polling a `MainWindow`
with plain `update()` calls instead of a real `mainloop()` reproduces the
`"main thread is not in main loop"` `RuntimeError` documented in
`tests/test_gui_integration.py`'s `_pump_until` docstring. This is a
constraint on *test/driver code*, not an application bug — `app.py` always
calls `window.mainloop()` — but it's worth restating here since it's easy
to reintroduce in ad hoc verification scripts.

## Notes / decisions

- `ScanResult` has no per-file timestamp (only the scan as a whole does —
  see the Run 5 status report's note on the results table). Both export
  functions take the scan's completion timestamp as a parameter and apply
  it to every CSV row / the JSON envelope, matching the same
  simplification `gui/results_view.py` already uses.
- The save-file dialog defaults to the app's `exports_dir`
  (`%LOCALAPPDATA%\SentinelLite\exports` on Windows, section 22) with a
  suggested filename `sentinellite_scan_<id>_<timestamp>.<ext>`, but the
  user can pick any writable location.
- Export only ever serializes the *last completed scan* held in memory —
  it does not re-run a scan or re-query the database — so "Export CSV"
  immediately after "Scan Now" is guaranteed to match what's on screen.
  Exporting a specific *historical* scan (from `list_scans()`) is part of
  the deferred scan-history UI, not this run.
