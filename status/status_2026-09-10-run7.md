## Notes / decisions

- No source code in `core/`, `storage/`, `gui/`, or `reports/` was
  changed this run. Per section 37 ("Do not blindly rewrite it... Correct
  deviations that materially affect MVP requirements"), a QA run that
  finds the existing implementation already correct should not invent
  changes merely to have a diff -- this run's scope was genuinely limited
  to packaging and final verification.
- The Linux-vs-Windows packaging gap is a property of this development
  environment (no Windows host container is available for the scheduled
  runs), not a deferred requirement -- `build_exe.bat` implements exactly
  section 21's preferred command and has been proven to work end-to-end
  on the one platform available. Anyone with access to a Windows machine
  can run `build_exe.bat` directly; no further code changes are expected
  to be needed for that build to succeed, based on the smoke test's
  results.
- Consistent with Run 6's note: `_pump_until`-style test/driver code must
  call a real `mainloop()`, not repeated `update()` polling, or CPython's
  tkinter raises `RuntimeError: main thread is not in main loop` when a
  background worker thread calls `self.after(...)`. This was
  re-encountered (and worked around, matching `tests/
  test_gui_integration.py`'s existing pattern) while writing this run's
  manual acceptance-test driver script -- restated here since it is easy
  to reintroduce in ad hoc verification code.
