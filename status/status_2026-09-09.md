## Notes / decisions

- Export always operates on whatever is currently displayed in the
  results table -- a fresh scan's results, or a scan loaded from history
  -- rather than re-reading the database, so what the user exports always
  matches what they were just looking at (including any active filter's
  underlying full result set; the export itself is always the full,
  unfiltered set of results, since exporting a partial view silently
  would be surprising).
  `results_view.results` intentionally returns the full unfiltered list
  even while a table filter (e.g. "Modified") is active, matching
  section 15's implication that an export represents the whole scan, not
  one filtered view of it.
- `_last_scan_id` is reset to `None` whenever the displayed results are
  cleared (folder change, new baseline) so a stale scan id is never
  attached to a JSON export; it is set from `save_scan`'s return value
  after a live scan, or from the selected `ScanMetadata.scan_id` after
  loading history.
- The scan-history dialog is a plain `tkinter.Toplevel` (not CustomTkinter)
  to keep `gui/dialogs.py` consistent with its existing use of stock Tk
  dialogs (`filedialog`, `messagebox`); it is modal (`grab_set` +
  `wait_window`) like the existing confirmation dialog.
