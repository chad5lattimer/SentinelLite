## Work performed this run

- Fetched `origin/main` and confirmed the working tree matched it exactly
  before making any change (no drift between runs).
- Ran the headless suite before any change: **54 passed, 16 skipped** —
  matches Run 11 exactly, no regressions.
- Installed `python3-tk` (Python 3.12) and a venv with `customtkinter`,
  then ran the full suite under `xvfb-run` before any change: **76
  passed, 4 skipped** — matches Run 11 exactly, no regressions.
- Rather than eyeballing the code for gaps, installed `pytest-cov` and
  measured actual line coverage across `core/`, `storage/`, `gui/`, and
  `reports/`. Real-display coverage stood at 95% overall, with concrete,
  named gaps:
  - `gui/main_window.py` (92%): the "Change Folder" dialog flow itself
    (`_on_change_folder`) was never called by any test — every existing
    test calls `_set_directory` directly to skip the folder picker. The
    guard clauses in `_on_create_baseline`/`_on_scan_now` (no directory,
    scan already running) were untested. The baseline-creation failure
    path (`_on_baseline_error`), the "unreadable files" warning log
    branch, the export-failure path (`OSError` during CSV/JSON write),
    and the "Scan Completed With Errors" status branch all existed as
    real, reachable error handling but had no test driving them.
  - `gui/results_view.py` (94%): `_sort_by` — the column-header click
    handler wired to `Treeview.heading(..., command=...)` that implements
    section 12's "sortable ... table" requirement — had zero coverage.
  - `core/baseline.py` (93%): the "log a warning per unreadable file"
    branch in `create_baseline`, and the defensive `BaselineNotFoundError`
    fallback in `find_baseline_for_directory` (a lookup finds a baseline
    id, but loading it races and fails), were both unexercised. The first
    is the same root cause Runs 10/11 already found twice: the existing
    chmod-based permission test correctly `pytest.skip()`s under root
    (this container runs as root), so it never reaches that branch here.
- Closed these gaps with tests only, at the same seams the production
  code already calls through (`core.baseline.create_baseline`,
  `core.scanner.run_scan`, `reports.exporter.export_csv`,
  `core.baseline.scan_directory`, `core.baseline.load_baseline`) so no
  new indirection or test-only hooks were added to production code:
  - `tests/test_gui_integration.py`: 15 new tests covering the real
    "Change Folder" dialog path (selected / cancelled / blocked while a
    scan is running), the `_on_create_baseline`/`_on_scan_now` guard
    clauses, a baseline-creation failure surfaced via a user-facing error
    dialog, unreadable files logged during baseline creation, a scan that
    completes with `ERROR` results showing "Scan Completed With Errors",
    an export write failure surfaced via a user-facing error dialog
    (success and failure dialogs are mutually exclusive), the fatal-error
    handler's own fallback when showing the error dialog itself fails,
    window close releasing the database connection, and the results
    table's column-sort toggling ascending/descending.
  - `tests/test_baseline.py`: 2 new tests — `create_baseline` logging a
    warning per unreadable file (via a monkeypatched `scan_directory`,
    so it runs under root too, unlike the pre-existing chmod-based test),
    and `find_baseline_for_directory` returning `None` instead of raising
    when a found baseline id fails to load.
- Re-ran the full suite after the change:

  - Real display (`xvfb-run`, Python 3.12 + `customtkinter` + `tkinter`):

  - Coverage: `gui/main_window.py`, `gui/results_view.py`,
