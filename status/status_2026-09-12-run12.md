## Work performed this run

- Fetched `origin/main`, confirmed the working tree matched it exactly,
  and ran the full suite before any change: **54 passed, 16 skipped**
  headless — matches Run 11 exactly, no regressions.
- Ran the suite with `--cov` for the first time this project (prior runs
  tracked pass/skip counts but not line coverage) and found `config.py`,
  `core/baseline.py`, and `core/filesystem.py` each had a handful of
  uncovered lines (93%/93%/90%; 97% combined for `core/`+`storage/`+
  `reports/`+`config.py`). Investigated why:
  - This container runs the test suite as **root** (`os.geteuid() == 0`),
    so the existing permission-bit tests in `test_filesystem.py`
    (`test_scan_directory_continues_after_permission_error`) and
    `test_baseline.py` (`test_create_baseline_excludes_unreadable_files`)
    skip themselves via their own `os.geteuid() == 0` guard — chmod(0)
    does not block root. That left the "unreadable file" `OSError` branch
    in `core/filesystem.scan_directory` and the "log a warning per
    unreadable file" loop in `core/baseline.create_baseline` genuinely
    untested in this environment (and in any other CI that happens to run
    as root).
  - `core/filesystem.py`'s `os.walk(..., onerror=...)` callback had no
    dedicated test at all — only real permission failures reached it,
    which have the same root-skips-it problem.
  - `core/baseline.find_baseline_for_directory`'s race-condition handling
    (`get_latest_baseline_id_for_directory` finds an id whose row is then
    missing when `load_baseline` runs) had no test.
  - `config._default_app_data_dir`'s Windows and macOS branches were
    never exercised on this Linux container (the packaged target is
    Windows-only, so this is expected, but the branches were still
    untested code).
- Closed all of the above with monkeypatch-based tests that do not depend
  on OS permission enforcement or the host platform, so they run
  identically as root or non-root, on Linux, macOS, or Windows:
  - `tests/test_filesystem.py`: `test_scan_directory_logs_and_continues_when_a_directory_cannot_be_listed`
    (simulated `os.walk` `onerror` callback) and
    `test_scan_directory_records_error_when_a_file_cannot_be_hashed`
    (simulated `calculate_sha256` failure).
  - `tests/test_baseline.py`: `test_create_baseline_logs_each_unreadable_file`
    (simulated `scan_directory` result with an unreadable file) and
    `test_find_baseline_for_directory_handles_disappeared_baseline`
    (simulated stale-id race via a monkeypatched repository lookup).
  - `tests/test_foundation.py`: `test_default_app_data_dir_on_windows`,
    `test_default_app_data_dir_on_windows_without_localappdata`, and
    `test_default_app_data_dir_on_macos` (monkeypatched `sys.platform` +
    environment).
- No production code was changed — this is test-only, additive coverage,
  matching the convention Runs 10 and 11 established.
- Re-ran the full suite after the change, with coverage:
