# SentinelLite — Status Report

**Date:** 2026-09-02
**Run:** 1 — Foundation

## Summary

The repository previously contained only the specification document
(`SentinelLite.md`). This run implements the Run 1 — Foundation objectives
from `PROJECT_SPEC.md` section 26: project structure, configuration,
logging, and a basic application entry point/window. No filesystem
scanning, hashing, or baseline logic has been implemented yet -- that is
scoped to Runs 2-4.

## Completed this run

- Repository/package structure created: `core/`, `storage/`, `gui/`,
  `reports/`, `tests/`, `assets/`, `data/`, `logs/`, `status/`.
- `config.py`: application metadata, cross-platform application-data path
  resolution (Windows `%LOCALAPPDATA%\SentinelLite`, with dev-friendly
  fallbacks and a `SENTINELLITE_DATA_DIR` override), and logging setup
  (`configure_logging`) writing to `<data_dir>/logs/sentinellite.log`.
- `app.py`: entry point that configures logging and launches the main
  window's event loop. Contains no scanning/hashing logic.
- `gui/main_window.py`: basic CustomTkinter window shell (header +
  placeholder Monitored Directory / Baseline / Scan / Status sections),
  matching the layout in `PROJECT_SPEC.md` section 11.2. All actions are
  currently disabled placeholders -- wiring happens in Run 5.
- `requirements.txt`: `customtkinter`, `pytest`, `pyinstaller` (everything
  else uses the standard library, per spec section 4.3).
- `README.md`: setup, run, and test instructions; project structure;
  application data location; security notes.
- `PROJECT_SPEC.md`: added as the canonical spec filename referenced
  throughout the spec's own operating instructions (mirrors
  `SentinelLite.md`, which is retained as the source document).
- `pytest.ini`, `.gitignore`.
- `tests/test_foundation.py`: covers app metadata, cross-platform path
  resolution, logging (log file is created and receives records), and
  that the main window builds, shows the expected title/labels, and
  tears down cleanly (run headlessly via Xvfb in this environment).

  headless GUI verification uses Xvfb and `SENTINELLITE_DATA_DIR` /
  XDG-style fallbacks for the application data directory during
  development. Windows path logic (`%LOCALAPPDATA%`) is implemented and
  will take effect automatically on Windows.
- `build_exe.bat` was intentionally not created this run -- it is not
  part of Run 1's listed deliverables and is scoped to Run 7 (Packaging).
