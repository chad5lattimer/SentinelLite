## Notes / decisions

- CSV/JSON exports reuse the same display-formatted timestamp string
  already shown in the results table (`ResultsView._timestamp`) for the
  export's `timestamp` field/column, rather than re-deriving one. This
  mirrors the Run 5 status report's documented simplification that the
  table's "Timestamp" column is the scan's completion time for every row
  (`ScanResult` has no per-file timestamp).
- The Scan History dialog lists scans for the **currently active
  baseline** only (`list_scans(connection, baseline_id=...)`), not every
  scan ever run against every baseline/folder. This matches the rest of
  the GUI's per-folder framing (`find_baseline_for_directory`, Run 5) and
  keeps the feature minimal per section 38 -- a cross-baseline history
  browser was not requested by the spec.
- `gui/history_dialog.py`'s `ScanHistoryDialog` is a plain `CTkToplevel`
  (not modal via `grab_set`/`wait_window`) so it stays simple to test and
  cannot deadlock the main window's background-task plumbing if left
  open during a scan; the "Scan History" button is disabled while a scan
  is in progress via the existing `_set_controls_enabled` mechanism.
- Export buttons are enabled purely based on whether `ResultsView` has
  results loaded (a live scan or a reloaded history entry) -- a history
  entry can be exported too, using the `scan_id`/`root_directory` it
  carries.
