# SentinelLite — Status Report

**Date:** 2026-09-02
**Run:** 2 — Hashing and Filesystem Engine

## Summary

This run implements the Run 2 objectives from `PROJECT_SPEC.md` section 27:
a standalone, GUI-independent core engine that recursively enumerates a
directory, hashes every readable file with SHA-256, and produces
`FileRecord` objects while tolerating per-file and per-directory errors.
No baseline, storage, or scan-comparison logic is implemented yet -- that
is scoped to Runs 3-4.

## Completed this run

- `core/models.py`: `FileRecord` dataclass (`path`, `sha256`, `size`,
  `modified_time`), per spec section 6.1.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable via `config.DEFAULT_HASH_CHUNK_SIZE`
  or a `chunk_size` argument) per spec section 7. Never loads a whole file
  into memory; raises `OSError` on unreadable files so callers can decide
  how to handle it (rather than silently masking failures).
- `core/filesystem.py`:
  - `iter_file_paths()` -- recursive traversal via `os.walk(followlinks=False)`
    with an `onerror` callback that logs and skips unlistable directories.
    Symbolic links (files and directories) are explicitly skipped -- see
    "Notes / decisions" below.
  - `build_file_record()` -- stats and hashes one file into a `FileRecord`
    with a root-relative, forward-slash path.
  - `scan_directory()` -- enumerates and hashes every file under a root,
    catching `OSError` per file and recording a `FileScanError(path, message)`
    instead of aborting the scan (spec section 8.3 / 7.3).
- `tests/test_hasher.py`: same-file/modified-file hashes, empty file,
  large (multi-chunk) file, chunk-size independence, invalid chunk size,
  missing file -- covers spec section 19 "Hashing" requirements.
- `tests/test_filesystem.py`: recursive enumeration over a nested tree,
  `FileRecord` field correctness, empty-directory handling, continuing
  the scan after an unreadable file (skipped automatically on
  environments that can't simulate a permission denial, e.g. running as
  root), and skipping symlinked files/directories.
- Updated `PROJECT_SPEC.md`, `SentinelLite.md`, and `README.md` status
  lines to reflect Run 2 completion.

## Notes / decisions

- Symbolic links are not followed, per spec section 8.2, which asks for
  this to be an explicit, documented choice: `os.walk(followlinks=False)`
  is used, plus an explicit symlink check on files and on directory
  entries before descending. This avoids symlink cycles and prevents a
  baseline from silently reaching outside the monitored directory.
- `core/hasher.py` raises rather than swallowing read errors -- the
  "don't crash the scan" requirement (section 7.3) is satisfied one layer
  up, in `core/filesystem.scan_directory()`, which is the single place
  that decides how to turn a per-file failure into a recorded result.
  This keeps the hashing primitive simple and independently testable.
- `FileScanError` (in `core/filesystem.py`, not `core/models.py`) is new,
  not explicitly named in the spec's data model section, but is needed to
  satisfy "Handle inaccessible files gracefully" (section 2.1) without
  losing which file failed and why. It is a filesystem/enumeration
  concern (distinct from the baseline/scan `ERROR` status defined in
  section 6.3), so it lives alongside `scan_directory()` rather than in
  `core/models.py`.
