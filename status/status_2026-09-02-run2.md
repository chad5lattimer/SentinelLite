## Completed this run

- `core/models.py`: `FileRecord` dataclass (`path`, `sha256`, `size`,
  `modified_time`), per spec section 6.1. Baseline/scan-result models
  are deliberately deferred to Runs 3-4, when something exists to
  produce/consume them.
- `core/hasher.py`: `calculate_sha256(file_path, chunk_size=...)`,
  reading files incrementally in configurable chunks (default from
  `config.DEFAULT_HASH_CHUNK_SIZE`, 1 MiB) so file size never bounds
  memory use, per spec section 7. Raises `OSError` on unreadable files;
  does not itself catch/log, since that policy belongs to the caller
  enumerating many files.
- `core/filesystem.py`: `iter_file_paths()` recursively walks a
  directory via `os.walk(..., followlinks=False)`, pruning symlinked
  directories and skipping symlinked files (documented decision, spec
  section 8.2) and logging+continuing past unlistable directories (spec
  section 8.3). `build_file_records()` hashes every enumerated file into
  a `FileRecord` with a forward-slash, root-relative path, and collects
  per-file failures as `FileAccessError` instead of raising, so one
  unreadable file cannot abort the rest (spec section 7.3).
- `tests/test_hasher.py`: identical/same-file hashing, modified-content
  hashing, empty file, large file via a small chunk size (exercises the
  multi-chunk loop), chunk-size invariance, missing-file error, invalid
  chunk size.
- `tests/test_filesystem.py`: recursive enumeration matching the
  directory shape from spec section 8, empty directory, `FileRecord`
  production and path/size correctness, hash-matches-direct-hash,
  simulated unreadable file continuing the scan, and symlinked
  file/directory are skipped rather than followed. This file is not
  named in spec section 5's test list (only `test_hasher.py` is), but is
  needed to exercise `core/filesystem.py`, which this run introduces --
  added as the simplest way to cover the new module without expanding
  scope elsewhere.

## Notes / decisions

- Symbolic links are never followed (files or directories) -- see the
  `core/filesystem.py` module docstring. This is the simplest safe
  behavior for the MVP per spec section 8.2, which only requires
  avoiding recursive symlink-following "unless explicitly determined to
  be safe"; no such determination was made.
- `build_file_records()` defaults its chunk size from
  `config.DEFAULT_HASH_CHUNK_SIZE` (imported lazily to avoid a
  module-level circular-import risk between `config` and `core`), so
  Run 3+ code can override it per call without touching `config`.
