## Work performed this run

- Rebuilt the two verification environments from scratch (headless
  Python 3.11 with no `tkinter`; a Python 3.12 + `customtkinter` +
  `python3-tk` environment run under `xvfb-run` for a real display).
- Ran the full suite **before any change**, confirming no drift from
  Run 12: headless **56 passed, 31 skipped**; real-display **93 passed,
  4 skipped** — both exact matches.
- Rather than declaring the project finished, measured actual line
  coverage again (`pytest-cov`) instead of relying on Run 12's own
  numbers. Overall coverage stood at 99%, with the same two named gaps
  Run 12 had explicitly flagged as "environment-dependent, already
  covered by tests that correctly skip" — but on inspection both were
  in fact closable without a non-root host or real Windows/macOS
  hardware:
  - `config.py` (93%): the Windows `%LOCALAPPDATA%` branch and the
    macOS `~/Library/Application Support` branch (section 22) were
    never exercised, because the only existing path test overrides
    `SENTINELLITE_DATA_DIR` entirely, bypassing `_default_app_data_dir`.
    `sys.platform` is just a string checked at call time, so it can be
    monkeypatched to exercise both branches on any host.
  - `core/filesystem.py` (90%): the "log a warning and continue" branch
    for an unreadable file (section 7.3) and for a directory that
    cannot be listed (section 8.3) were only covered by a real
    `chmod`-based test that correctly `pytest.skip()`s under root
    (this container, like the CI environment prior runs also ran in,
    runs as root). Both branches call through a seam
    (`core.filesystem.calculate_sha256`, `os.walk`'s `onerror`
    callback) that can be monkeypatched to simulate the failure
    directly, the same pattern Runs 10-12 used for `storage/`,
    `gui/dialogs.py`, and `core/baseline.py`.
- Closed both gaps with tests only, at existing seams, adding no new
  indirection to production code:
  - `tests/test_foundation.py`: 3 new tests —
    `_default_app_data_dir()` on a monkeypatched Windows platform with
    `LOCALAPPDATA` set, the same branch with `LOCALAPPDATA` unset (the
    `~/AppData/Local` fallback), and on a monkeypatched macOS platform.
  - `tests/test_filesystem.py`: 2 new tests — `scan_directory` recording
    an `ERROR` result and logging a warning when `calculate_sha256`
    raises `OSError` for one file (kept alongside, not instead of, the
    existing real-`chmod` test), and `scan_directory` logging a warning
    and continuing when `os.walk`'s `onerror` callback fires for an
    unlistable subdirectory.
- Re-ran the full suite after the change:
  - Headless: **61 passed, 31 skipped** (+5 from the new tests, all of
    which run without a display; 0 regressions).
  - Real display (`xvfb-run`): **98 passed, 4 skipped** (+5, 0
    regressions). The remaining 4 skips are the original real-`chmod`
    tests, which still correctly skip under root and are kept as
    genuine regression coverage for non-root hosts even though the new
    monkeypatched tests now also exercise those lines everywhere.
  - Coverage: **100% line coverage across the entire project**
    (`config.py`, `core/`, `storage/`, `gui/`, `reports/` all at 100%).
- Cross-checked `PROJECT_SPEC.md` and `SentinelLite.md` — kept
  byte-identical, as the existing convention requires; updated the
  Development Progress paragraph to record this run.
