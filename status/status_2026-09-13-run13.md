  purposes (as opposed to true end-to-end platform coverage):
  `_default_app_data_dir()` is a pure function of `sys.platform` and
  `os.environ`, and `core/filesystem.py`'s error branches only need
  `os.walk`/`calculate_sha256` to behave a certain way — both can be
  monkeypatched directly, exactly as Runs 10-12 already did for the
  storage, dialogs, and baseline/GUI gaps they closed. No prior run had
  actually attempted this for these two modules.
- Closed both gaps with tests only, at the same seams the production code
  already calls through (`config.sys.platform`, `os.environ`,
  `core.filesystem.os.walk`, `core.filesystem.calculate_sha256`), adding
  no new indirection or test-only hooks to production code:
  - `tests/test_foundation.py`: 5 new tests — `_default_app_data_dir()`
    on Windows with `%LOCALAPPDATA%` set, on Windows without it (home
    fallback), on macOS, on Linux with `XDG_DATA_HOME` set, and on Linux
    without it (home `.local/share` fallback).
  - `tests/test_filesystem.py`: 2 new tests — a monkeypatched `os.walk`
    that invokes the `onerror` callback for an unlistable directory
    (verifying the scan continues and logs a warning), and a
    monkeypatched `calculate_sha256` that raises `PermissionError` for
    one file (verifying it is recorded as a `FileError` rather than
    aborting the scan).
