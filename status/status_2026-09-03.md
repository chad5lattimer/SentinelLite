## Completed this run

- `core/models.py`: `FileRecord` (relative path, sha256, size,
  modified_time), `FileAccessError` (path + message for files that
  couldn't be read), and the `ScanStatus` enum (`NEW`, `MODIFIED`,
  `DELETED`, `UNCHANGED`, `ERROR`) from spec section 6, shared ahead of
  time so Runs 3-4 (baseline/scanner) have a single definition to import.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable via
  `config.DEFAULT_HASH_CHUNK_SIZE`/parameter). Raises `OSError` on
  unreadable files rather than swallowing errors itself; callers decide
  how to handle that (section 7.3).
- `core/filesystem.py`:
  - `iter_files()` -- recursively walks a directory with `os.walk`,
    skipping symbolic links (both directories and files) by default and
    logging (not raising on) directories that can't be listed. Symlink
    behavior is documented per section 8.2: links are not followed by
    default, to avoid escaping the monitored root or looping on cyclic
    links.
  - `build_file_records()` -- enumerates and hashes every file under a
    root directory, returning a `FilesystemScanResult(records, errors)`.
    A file that can't be hashed (permission error, removed mid-scan,
    etc.) is logged and added to `errors`; it never aborts the rest of
    the scan (sections 7.3, 8.3).
- Tests: `tests/test_hasher.py`, `tests/test_filesystem.py`,
  `tests/test_models.py` -- covering the section 19 hashing requirements
  (same file → same hash, modified file → different hash, empty file,
  large file hashed incrementally against a `hashlib` reference),
  recursive enumeration matching the section 8 example tree, relative
  POSIX-style paths, permission-error handling (via both a monkeypatched
  hasher and, where the test process isn't running as root, a real
  `chmod`), and symlinked files/directories being skipped.

## Notes / decisions

- Symlinks (files and directories) are skipped entirely by default,
  rather than partially followed -- the simplest behavior that satisfies
  section 8.2 without introducing traversal-loop or root-escape risk.
  `follow_symlinks=True` exists as an explicit opt-in parameter but is
  not used anywhere in the application.
- `ScanStatus` was added to `core/models.py` now (rather than deferred to
  Run 4) since it's a pure data definition with no logic and Run 4's
  `core/scanner.py` will need it; this keeps a single canonical
  definition rather than one being added later and needing to move.
- Root-owned dev container: one permission-handling test is
  environment-conditional (`os.geteuid() == 0`) since `chmod(0o000)`
  doesn't block root reads; the primary permission-error test uses
  `monkeypatch` instead so the important behavior (an unreadable file is
  recorded as an error, not raised) is actually exercised in this
  environment too.
