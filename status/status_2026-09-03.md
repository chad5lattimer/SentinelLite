## Summary

This run implements the Run 2 objectives from `PROJECT_SPEC.md` section 27:
the core hashing and filesystem-enumeration engine. Run 1's foundation

intact and unchanged. No GUI wiring, baseline persistence, or scan

## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time — per
  spec section 6.1) and `FileAccessError` (path, message), a small data
  type used to report a file that could not be read without aborting the
  scan (sections 7.3 / 8.3). The baseline container and scan-result status
  model (sections 6.2 / 6.3) are intentionally deferred to Runs 3-4,
  alongside the code that produces them.
- `core/hasher.py`: `calculate_sha256(file_path, chunk_size)` — incremental,
  chunked SHA-256 hashing (default chunk size 1 MiB, from
  `config.DEFAULT_HASH_CHUNK_SIZE`) so large files are never loaded fully
  into memory. Raises `OSError` on unreadable files; callers are
  responsible for catching it (per section 7.3).
- `core/filesystem.py`:
  - `enumerate_files(root, follow_symlinks=False, onerror=...)` —
    recursive traversal via `os.walk`. Symlinked directories are **not**
    followed by default (section 8.2 requires this behavior be documented
    and chosen deliberately): this avoids symlink cycles and silently
    pulling files from outside the monitored root into the baseline.
    Directories that cannot be listed are skipped, not fatal (section 8.3).
  - `build_file_records(root, chunk_size, follow_symlinks=False)` —
    enumerates and hashes every file, returning
    `(list[FileRecord], list[FileAccessError])`. A file that cannot be
    hashed (permission denied, disappears mid-scan, etc.) is logged and
    added to the error list; enumeration continues with the remaining
    files (sections 7.3 / 8.1 / 8.3). Relative paths use forward slashes on
    every platform for portable baselines.
- `tests/test_hasher.py`: same file → same hash, modified file → different
  hash, empty file, chunked hashing of a larger file cross-checked against
  `hashlib` directly, invalid chunk size, missing file.
- `tests/test_filesystem.py`: recursive enumeration (including nested
  directories), directories are never yielded as files, correct
  `FileRecord` fields (hash/size/mtime) and forward-slash relative paths,
  empty directory, an unreadable file is recorded as a `FileAccessError`
  while the rest of the scan still completes, an unreadable *directory* is
  likewise recorded and skipped (skipped automatically when running as
  root, since permission bits aren't enforced), and a symlinked directory
  pointing outside the monitored root is not followed by default.

## Notes / decisions

- Symlinked directories are not followed by default, per section 8.2 —
  documented above and in `core/filesystem.py`'s module docstring. This is
  the "simplest, safest" interpretation available where the spec leaves
  the exact behavior to be determined; a `follow_symlinks=True` override
  exists on both public functions if a future run needs it, but nothing
  currently opts in.
- `core/models.py` currently defines only what Run 2 needs
  (`FileRecord`, `FileAccessError`). `Baseline` and the `ScanResult`/status
  enum from spec section 6 will be added when the baseline (Run 3) and
  scanner (Run 4) modules that produce them are implemented, to avoid
  speculative, untested data structures.
- No changes were needed to Run 1's foundation code; it was verified
  working as-is and left untouched.
