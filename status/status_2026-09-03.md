# SentinelLite — Status Report

**Date:** 2026-09-03
**Run:** 2 — Hashing and Filesystem Engine

## Summary

Implements PROJECT_SPEC.md section 27 (Run 2): the SHA-256 hashing and
recursive filesystem enumeration engine, with no GUI wiring beyond what
already existed from Run 1.

## Completed this run

- `core/models.py`: `FileRecord` (relative path, sha256, size,
  modified_time) per spec section 6.1, plus a small `FileError` type used
  to represent a file/directory that could not be read.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable via
  `config.DEFAULT_HASH_CHUNK_SIZE`, per spec section 7.2). Read failures
  raise `FileHashError` rather than crashing the caller (spec 7.3).
- `core/filesystem.py`:
  - `enumerate_files()` -- recursive directory walk producing absolute
    file paths, using `os.walk(..., followlinks=False)`. Symbolic links
    are not followed: a symlinked directory is not recursed into, and a
    symlinked file is skipped. This is documented in the module
    docstring per spec section 8.2, which leaves the exact behavior to
    be chosen and documented.
  - `hash_directory()` -- enumerates and hashes every file under a root,
    returning `(records, errors)`. Per-file read failures (and
    directory-listing permission errors from `os.walk`'s `onerror`
    hook) are captured as `FileError` entries instead of raising, so one
    bad file never aborts the scan (spec sections 7.3, 8.3). Accepts an
    optional `on_progress(files_done, relative_path)` callback so the
    GUI (Run 5) can display progress without this module depending on
    any GUI toolkit.
  - Relative paths are stored using POSIX separators (`Path.as_posix()`)
    so baselines are portable across platforms, per spec section 6.2.
- `tests/test_hasher.py` (10 tests) and `tests/test_filesystem.py` (9
  tests): cover the Run 2 acceptance criteria and spec section 19
  (Hashing) requirements -- same file/same hash, modified file/different
  hash, empty file, large (non-chunk-aligned) file, chunk-size
  independence, missing/unreadable files raising `FileHashError`,
  nested-directory enumeration, POSIX-style relative paths, progress
  callback invocation, per-file error handling without aborting the
  scan, and that symlinked directories/files are not followed.

## Notes / decisions

- Symlink policy (spec 8.2): do not follow symlinked directories or
  files. Chosen because the MVP has no requirement to reason about links
  that may point outside the monitored root or change target between
  baseline creation and a later scan; this keeps hashing well-defined
  and avoids infinite-loop risk from cyclic links. Documented in
  `core/filesystem.py`.
- `test_unreadable_path_raises_file_hash_error` hashes a *directory*
  path rather than a chmod'd file, since this sandbox runs as `root`,
  which can read past permission bits -- a directory can never be
  opened as a regular file regardless of user, so it reliably exercises
  the same `OSError` → `FileHashError` path on any platform/user.
- No database, baseline, or scan-comparison logic was added -- that is
  explicitly Run 3 (Baseline System) and Run 4 (Comparison and Scan
  Engine) scope, per the spec's run-by-run plan and section 38 (Scope
  Control Rule).
