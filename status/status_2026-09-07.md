## Completed this run

- `storage/database.py`: `get_connection()` opens (and creates if needed)
  the SQLite database at `config.PATHS.database_path`, with foreign keys
  enabled and `sqlite3.Row` access. `initialize_schema()` creates the four
  tables from `PROJECT_SPEC.md` section 14 -- `baselines`,
  `baseline_files`, `scans`, `scan_results` -- plus supporting indexes.
  The `scans`/`scan_results` tables are created now (schema defined in one
  place) but are not read or written until Run 4.
- `storage/repository.py`: `BaselineRepository`, wrapping a SQLite
  connection:
  - `save(baseline)` -- persists a baseline and its files transactionally,
    **replacing** any existing baseline for the same `root_directory`
    (spec section 9: creating a baseline replaces the monitoring
    reference).
  - `load_latest_for_directory(root_directory)` / `load_by_id(id)` --
    reload a saved baseline, raising `BaselineNotFoundError` when none
    exists and `BaselineCorruptedError` when the stored data cannot be
    read back (spec section 19 requires both to be handled explicitly).
  - `exists_for_directory(root_directory)` -- for future GUI use (Run 5)
    deciding whether to show "Baseline Ready" vs. "No baseline exists".
- `core/baseline.py`: `Baseline` dataclass (`baseline_id`, `created_at`,
  `root_directory`, `application_version`, `files`) per spec section 6.2.
  `create_baseline(root_directory, repository, progress_callback=None)`
  composes `core.filesystem.scan_directory()` with the repository to
  enumerate, hash, and save a new baseline, returning the saved baseline
  plus any per-file errors (which do not block baseline creation from the
  files that *were* readable). `load_baseline(root_directory, repository)`
  reloads the current baseline for a directory.
- `tests/test_storage.py`: schema creation, idempotent re-initialization,
  save/load round-trip, loading the latest baseline by directory,
  replacement of a prior baseline for the same directory, missing-baseline
  and corrupted-baseline errors, and rejecting a non-SQLite file at the
  database path.
- `tests/test_baseline.py`: the full acceptance scenario from spec section
  28 (create directory -> create files -> create baseline -> modify
  filesystem -> reload baseline -> baseline unchanged), baseline
  replacement, missing/corrupted baseline handling, and continuing to
  save a baseline after an unreadable file.

## Notes / decisions

- `BaselineRepository.save()` deletes and re-inserts the baseline for a
  directory inside a single `sqlite3` transaction (`with self._connection:`)
  so a failure partway through cannot leave the database with no baseline
  or a half-written one for that directory.
- The `scans`/`scan_results` tables are created in this run's schema
  (rather than deferred to Run 4) purely so `storage/database.py` defines
  the whole schema in one place; no code in this run reads or writes them.
- `BaselineCorruptedError` is deliberately distinct from
  `BaselineNotFoundError` per spec section 19, so a future GUI (Run 5) can
  show "no baseline yet, create one" vs. "your baseline is damaged,
  re-create it" rather than conflating the two.
