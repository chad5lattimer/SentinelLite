## Notes / decisions

- `create_baseline()` silently excludes files that failed to hash (rather
  than raising) since an unreadable file cannot be part of a cryptographic
  trust reference; callers get the excluded files back as `FileError`s to
  surface to the user, consistent with the "continue processing, inform
  the user after" pattern already used by `core.filesystem.scan_directory`.
- `BaselineRepository.save()` is additive (new row per baseline) rather
  than overwriting, which is both simpler and safer than an in-place
  update/delete -- it naturally satisfies "prevent accidental silent
  replacement" at the storage layer without needing storage to know about
  GUI confirmation state.
- Corruption handling lives in `storage/repository.py` rather than
  `storage/database.py` because translating a raw `sqlite3.DatabaseError`
  into `BaselineValidationError` requires importing from `core.baseline`;
  per the layered architecture, `storage/database.py` (the lowest layer)
  must not depend on `core`, so the repository (the layer directly above
  storage) does the translation.
