## Completed this run

- `core/models.py`: `FileRecord`, `FileAccessError`, `ScanStatus`, and
  `ScanResult` dataclasses (section 6's data model). `ScanStatus`/
  `ScanResult` are defined now, alongside `FileRecord`, since they are
  plain data containers with no logic and `core/scanner.py` (Run 4) will
  need them without re-touching `models.py`.
- `core/hasher.py`: `calculate_sha256()` — incremental, chunked SHA-256
  hashing (default 1 MiB chunks, configurable), per section 7. Raises
  `OSError` on unreadable files rather than swallowing errors itself;
  callers decide how to handle that (section 7.3).
- `core/filesystem.py`:
  - `iter_files()` — recursive directory walk via `os.walk`.
  - `enumerate_and_hash()` — enumerates + hashes every file, returning
    `(records, errors)`. Continues past unreadable/deleted-mid-scan files
    instead of raising, and reports progress via an optional callback for
    later GUI use (section 13).
  - **Symlink decision (section 8.2):** symbolic links (files and
    directories) are skipped by default and not followed, to avoid
    escaping the monitored directory or infinite loops; documented in the
    module docstring. `follow_symlinks=True` is available if a future run
    needs it.
- `tests/test_hasher.py`: same-file/modified-file hashes, a known SHA-256
  test vector, empty-file hashing, large/chunked-read consistency, missing
  file raises `OSError`, invalid chunk size raises `ValueError`.
- `tests/test_filesystem.py`: recursive enumeration matches the example
  tree in section 8, symlinked files/dirs are skipped, `FileRecord`s are
  produced with correct hash/size, progress callback fires once per file,
  an unreadable file is recorded as an error and the scan continues, a
  file deleted mid-scan (TOCTOU) is handled the same way, and an empty
  directory produces no records/errors.
