## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) and
  `FileError` (path, message) frozen dataclasses, per spec section 6.1.
- `core/hasher.py`: `calculate_sha256()` -- incremental, chunked SHA-256
  hashing via `hashlib`, using the configurable chunk size already
  defined in `config.py` (default 1 MiB, spec section 7.2). Read errors
  propagate as `OSError` for the caller to handle; a non-positive
  `chunk_size` raises `ValueError`.
- `core/filesystem.py`:
  - `iter_files()` -- recursively yields every regular file under a root
    directory using `os.walk(followlinks=False)`. Symbolic links (both
    symlinked files and symlinked directories) are skipped rather than
    followed -- the chosen and documented behavior for spec section 8.2,
    avoiding directory cycles and silent scope-escape outside the
    monitored root. Directory-listing errors are logged and that
    directory is skipped without aborting enumeration (section 8.3).
  - `collect_file_records()` -- enumerates and hashes every file under a
    root, returning a `FileCollectionResult(records, errors)`. A file
    that cannot be read produces a `FileError` and processing continues
    with the rest of the tree (sections 7.3 / 8.3); it does not raise.
  - Contains no GUI code, per the layered architecture in spec section 5.
- `tests/test_hasher.py` (7 tests): same-file/same-hash, modified file
  produces a different hash, empty file, a ~6 MiB file with a small
  chunk size to force multiple reads, chunk-size independence of the
  result, missing-file error, invalid chunk size.
- `tests/test_filesystem.py` (7 tests): recursive enumeration across
  nested subdirectories, symlinked file skipped, symlinked directory not
  descended into, correct hashes/paths/sizes from `collect_file_records`,
  continuing past an unreadable file (simulated via monkeypatch, since
  this environment runs as root where `chmod`-based permission tests are
  unreliable) with the resulting `FileError` recorded, empty-directory
  handling, and relative/posix-style path output.

## Notes / decisions

- Symlinks are not followed (documented in `iter_files`'s docstring, per
  the explicit requirement in spec section 8.2 to document the chosen
  behavior).
- `collect_file_records` returns errors as data (`FileCollectionResult`)
  rather than raising, so a future scan engine (Run 4) can decide how to
  surface them (e.g. as `ERROR` scan results) without `core.filesystem`
  needing to know about that concept yet -- keeping this run's scope to
  enumeration/hashing only.
- Permission-error handling is tested via monkeypatching
  `core.filesystem.calculate_sha256` rather than `chmod`, because this
  development container runs as root, where Unix permission bits do not
  restrict access and a `chmod`-based test would not actually exercise
  the error path.
