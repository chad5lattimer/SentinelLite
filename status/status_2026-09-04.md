## Summary

This run implements the Run 2 objectives from `PROJECT_SPEC.md` section 27:

## Completed this run

- `core/models.py`: `FileRecord` dataclass (relative path, SHA-256, size,
  modified time), per PROJECT_SPEC.md section 6.1.
- `core/hasher.py`: `calculate_sha256()` — incremental, chunked SHA-256
  hashing (default 1 MiB chunks via `config.DEFAULT_HASH_CHUNK_SIZE`,
  configurable) so large files are never fully loaded into memory, per
  section 7.2. Raises `OSError` on unreadable files rather than swallowing
  errors, so callers can decide how to handle them.
- `core/filesystem.py`:
  - `iter_files()` — recursive directory traversal via `os.walk`.
    Symbolic links are **not followed by default** (documented decision
    per section 8.2): a symlinked file is skipped, and a symlinked
    directory is not descended into, to avoid cyclical recursion and
    silently expanding the monitored tree. Directory-listing permission
    errors are handled via `os.walk`'s `onerror` callback and logged
    rather than raised, so traversal continues into sibling directories
    (section 8.3).
  - `collect_file_records()` — enumerates a directory and hashes every
    readable file, returning `(records, errors)`. A file that cannot be
    hashed (e.g. a permission error) is recorded as a `FileAccessError`
    and logged; processing continues with the remaining files (section
    7.3). Uses relative, POSIX-style paths (section 6.2).
- `tests/test_hasher.py` (9 tests): same file → same hash, modified file →
  different hash, empty file, a reference-implementation comparison
  against `hashlib` directly, chunked reads on a multi-chunk file (with a
  test that counts `read()` calls to confirm hashing is incremental, not
  a single full-file read), invalid chunk size, and a missing file
  raising `OSError`.
- `tests/test_filesystem.py` (6 tests): recursive enumeration and
  per-directory sort order, symlinked file skipped by default, symlinked
  directory not descended into, traversal continues past a simulated
  directory permission error, `FileRecord` construction (path/size/hash
  length), a file that fails to hash is reported as an error while
  sibling files still succeed, and relative POSIX path correctness for
  nested directories.

## Notes / decisions

- Symlink handling (section 8.2 asks that the chosen behavior be
  documented): symlinks are not followed by default in either
  `iter_files()` or the underlying `os.walk` call. This is the safer
  default for an integrity monitor and matches the spec's guidance to
  avoid following links "unless explicitly determined to be safe". A
  `follow_symlinks=True` parameter exists on `iter_files()` for future
  use but is not exposed anywhere yet (no scope for it in the MVP GUI).
- `core/filesystem.py` returns errors as data (`FileAccessError` list)
  rather than raising, so the future scan engine (Run 4) and baseline
  creation (Run 3) can decide how to surface "N files could not be read"
  to the user without re-deriving that logic.
- Kept `core/models.py` limited to `FileRecord` for this run. The
  `ScanStatus`/scan-result shape described in PROJECT_SPEC.md section 6.3
  belongs to the comparison engine and is deferred to Run 4, per the
  scope-control rule in section 38 (smallest reasonable change for the
  current run).
