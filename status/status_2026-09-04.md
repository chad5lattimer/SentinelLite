## Completed this run

- `core/models.py`: `FileRecord` (path, sha256, size, modified_time) per
  spec section 6.1, plus `FileAccessError` (path, message) to carry
  per-file read failures out of the engine without raising, so scans
  never abort on one bad file (section 7.3 / 8.3).
- `core/hasher.py`: `calculate_sha256()` — incremental, chunked SHA-256
  hashing (default chunk size from `config.DEFAULT_HASH_CHUNK_SIZE`, 1
  MiB) so large files are never fully loaded into memory. Read errors
  propagate as standard `OSError` subclasses for the caller to handle.
- `core/filesystem.py`:
  - `iter_files()` — recursive traversal via `os.walk`, yielding files
    only (not directories). Symbolic links are **not** followed by
    default (documented decision per section 8.2: avoids link cycles and
    content from outside the monitored tree); `follow_symlinks=True` opts
    in. Directory-listing permission errors are logged and that
    subdirectory is skipped rather than aborting the whole walk (8.3).
  - `build_file_record()` — hashes one file and returns a `FileRecord`
    with a relative, forward-slash (`Path.as_posix()`) path so baselines
    stay portable, per section 6.2.
  - `collect_file_records()` — enumerates + hashes an entire tree,
    catching `OSError` per file, collecting it as a `FileAccessError`,
    and continuing with the rest (7.3). Accepts an optional
    `progress_callback(count, path)` for later GUI progress-bar wiring
    (Run 5) without the engine knowing anything about the GUI.
- `tests/test_hasher.py` (9 tests): same-file/same-hash, hash matches a
  `hashlib` reference, modified file produces a different hash, empty
  file, a 50 KiB file hashed across many small chunks (verifies the
  incremental-read path, not just a single `read()`), digest shape
  (64 lowercase hex chars), missing file raises `OSError`, invalid chunk
  size raises `ValueError`, and unreadable file raises `PermissionError`
  (skipped when running as root, where permission bits aren't enforced).
- `tests/test_filesystem.py` (10 tests): recursive enumeration matches a
  known tree exactly, only files (never directories) are yielded, relative
  POSIX paths are produced correctly for nested files, every file in a
  tree gets hashed correctly, progress callback fires once per file with
  the right paths, an empty directory yields no records/errors, an
  unreadable file is recorded as a `FileAccessError` while the rest of the
  scan continues (skipped as root), and symlinked files are skipped by
  default but included when `follow_symlinks=True` is passed explicitly
  (skipped on Windows).

## Notes / decisions

- Symlinked files are excluded from scans by default (section 8.2 leaves
  this an implementation decision, provided it's documented). This is the
  conservative choice: it prevents scans from silently following links
  outside the monitored directory and avoids link-cycle risk. Callers that
  have determined it's safe can pass `follow_symlinks=True`.
- `core/models.py` was kept to just `FileRecord` and `FileAccessError` for
  this run. The `ScanResult`/status-enum shape described in spec section
  6.3 (NEW/MODIFIED/DELETED/UNCHANGED/ERROR) belongs to the comparison
  engine and is deferred to Run 4 (`core/scanner.py`), per the scope
  control rule in section 38 — defining it now, unused, would be premature.
- Three tests are conditionally skipped when the process has root
  privileges (`os.geteuid() == 0`) or on Windows, since POSIX permission
  bits/symlinks aren't meaningfully testable in those cases; this mirrors
  how the Run 1 test suite already adapted to the Linux/Xvfb sandbox.
