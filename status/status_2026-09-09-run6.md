## Completed this run

- `reports/exporter.py` (new): `export_csv()` and `export_json()`. Pure
  formatting/serialization with no GUI, hashing, or comparison logic
  (section 5) -- callers supply already-computed `core.scanner.ScanResult`
  objects and a destination path.
  - CSV columns exactly match section 15.1:
    `status,path,baseline_hash,current_hash,size,timestamp`.
  - JSON shape exactly matches section 15.2:
    `scan_id`, `timestamp`, `root_directory`, `summary` (modified/new/
    deleted/unchanged/errors), `results`.
  - Missing `baseline_hash`/`current_hash` (NEW/DELETED results) write as
    empty CSV fields / JSON `null`, not the literal string `"None"`.
  - Parent directories are created automatically so export works whether
    or not the target folder already exists.
- `gui/dialogs.py`: added `choose_save_file()` -- a thin wrapper around
  `tkinter.filedialog.asksaveasfilename`, consistent with the existing
  folder-picker/confirmation/info-dialog wrappers.
- `gui/results_view.py`: added "Export CSV" / "Export JSON" buttons next
  to the filter control. Disabled whenever there are no results to export
  (no scan yet, or the results were just cleared by a folder/baseline
  change); enabled the moment `set_results()` receives at least one
  result. The view only renders the buttons and forwards clicks via
  `on_export_csv`/`on_export_json` callbacks -- it does not know how to
  write a file, keeping export I/O out of the presentation layer.
- `gui/main_window.py`:
  - `_run_scan_worker`/`_on_scan_complete` now also capture the saved
    scan's database id (`save_scan`'s return value), so export doesn't
    need to re-derive or re-run anything.
  - New `_on_export_csv`/`_on_export_json`/`_export_results()`: prompt for
    a destination (defaulting to the app's `exports/` data directory,
    section 22), call into `reports.exporter`, and show a friendly
    success/error dialog (section 18) -- an `OSError` during export (e.g.
    an unwritable destination) is caught and surfaced without crashing.
  - Selecting a different folder or creating a new baseline now also
    clears the last scan's exportable state (`_clear_last_scan`), so a
    stale scan's results can't be exported under a new folder/baseline.
- `tests/test_reports.py` (new): CSV header/rows/paths, JSON validity and
  summary counts, `None` hash/size fields round-tripping correctly, and
  parent-directory creation for both formats.
- `tests/test_gui_integration.py`: added export-specific coverage --
  buttons stay disabled until a scan has results, a full scan ->
  export-CSV -> export-JSON flow produces accurate files (the Run 6
  acceptance scenario), cancelling the save dialog is a no-op, and
  switching folders clears the previous scan's exportable state.
- Updated `PROJECT_SPEC.md`, `SentinelLite.md`, and `README.md` progress
  banners.

## Notes / decisions

- Export defaults to the app's per-user `exports/` data directory
  (`config.PATHS.exports_dir`, section 22) as the save dialog's initial
  directory, but the user can choose any writable location.
- The default filename is `sentinellite_scan_<scan_id>.<csv|json>`, tying
  the export back to its `scans` table row.
- `_last_scan_results`/`_last_scan_id`/`_last_scan_timestamp_iso` are
  reset whenever the results table is cleared (new folder selected, new
  baseline created) so the export buttons and any exported file always
  correspond to the currently-displayed scan, never a stale one from a
  previously monitored folder.
