## Completed this run

- `reports/exporter.py` (new): `export_csv()` and `export_json()`, per
  section 15.1/15.2. Pure functions -- they take already-computed
  `core.scanner.ScanResult` objects and a destination path, and contain no
  hashing/filesystem/GUI logic (section 5). Both create parent directories
  as needed and handle an empty result set (e.g. an empty monitored
  directory) without error.
- `gui/main_window.py`: added "Export CSV" / "Export JSON" buttons below
  the results table, disabled until a scan has completed and re-disabled
  whenever the monitored folder changes or a new baseline is created
  (since either invalidates the currently-displayed scan). Export uses a
  native "Save As" dialog defaulting to the per-user exports directory
  (`config.PATHS.exports_dir`, section 22) with a suggested filename of
  `sentinellite_scan_<scan_id>.csv`/`.json`. A write failure (e.g.
  read-only destination) shows a friendly error dialog rather than a
  traceback (section 18) and is logged; success is logged and confirmed
  with a dialog naming the destination (section 16: "Export operations").
- `gui/dialogs.py`: added `choose_save_file()`, a thin wrapper around
  `tkinter.filedialog.asksaveasfilename`, isolated from window
  layout/state like the existing folder-picker/confirmation dialogs.
- `gui/results_view.py`: added a public `results` property so export
  always writes the *complete* scan (all statuses), not just whatever
  subset the results table happens to be filtered to at the time.
- `core/scanner.py` / `storage/repository.py`: no changes needed --
  `save_scan()` already returned the new scan's id, which the GUI now
  captures and threads through to export.
- `tests/test_reports.py` (new): CSV header/row content and path order,
  JSON shape/validity (`json.loads` round-trip) matching section 15.2,
  correct summary counts, empty-result-set export, and that missing
  hash/size fields serialize as `""` in CSV rather than the string
  `"None"`.
- `tests/test_gui_integration.py`: export-button enabled/disabled state
  across folder switches and baseline re-creation, an end-to-end
  scan -> export CSV -> export JSON test asserting on-disk file content,
  and that cancelling the save dialog writes nothing.
- Updated `PROJECT_SPEC.md`, `SentinelLite.md`, and `README.md` progress
  banners.

## Notes / decisions

- `ScanResult` (and the `scan_results` table) records one timestamp per
  scan, not per file. Consistent with how the Run 5 results table already
  displays a single scan-completion timestamp for every row, both
  `export_csv` and `export_json` do the same -- documented in
  `reports/exporter.py`'s module docstring rather than expanding the data
  model mid-run.
- JSON export includes `size` and `error_message` per result in addition
  to the fields shown in section 15.2's minimal example, since both are
  already part of `ScanResult` and dropping them would make the JSON
  export strictly less useful than the CSV export (which does need `size`
  per section 15.1). The required fields (`scan_id`, `timestamp`,
  `root_directory`, `summary`, `results`) all match the example shape
  exactly.
- Export always writes every result in the current scan (`results_view`'s
  new `results` property), not just the rows visible under the active
  table filter -- exporting a silently-truncated report because the user
  happened to have "Modified" selected would be a correctness bug, not a
  convenience.
