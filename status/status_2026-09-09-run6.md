## Notes / decisions

- Export buttons live in a new "Reports" section of the main window
  (between the Scan section and the progress bar) rather than inside
  `ResultsView`, because exporting needs `scan_id` and
  `root_directory` (for JSON, section 15.2), which `ResultsView` doesn't
  own -- keeping that data in `MainWindow` avoids widening
  `ResultsView`'s responsibilities.
- The main window now tracks "the last scan shown" (`_last_scan_id`,
  `_last_scan_results`, `_last_scan_timestamp`) rather than only "the
  last scan run" -- reloading an older scan from Scan History updates
  the same state, so Export CSV/JSON always exports whatever is
  currently on screen, consistent with the spec's `Scan -> View results
  -> Export` flow (section 31's acceptance criteria) whether "View
  results" came from a fresh scan or from history.
- `ScanHistoryDialog` reads directly through the GUI thread's existing
  `self._connection` (history lookups are small indexed reads, not
  worth a background thread) -- consistent with how folder selection
  already uses that connection in Run 5.
