## Notes / decisions

- `run_scan()` requires the caller to have already loaded/saved the
  baseline (mirrors `core.baseline`'s split between in-memory creation and
  persistence): it does not itself call `load_baseline()`, so the GUI
  (Run 5) controls which baseline a scan runs against and can display
  "No baseline exists" (section 24) before ever calling into the scanner.
- Results are sorted by relative path before being returned/persisted, so
  the results table (Run 5) and exports (Run 6) get stable, predictable
  ordering without needing their own sort step.
- A path that both fails to hash *and* is absent from the baseline is
  still reported as a single `ERROR` (not `NEW` and not `DELETED`) --
  its current content is unknown, so claiming it is new or unchanged
  would overstate what the tool actually verified.
