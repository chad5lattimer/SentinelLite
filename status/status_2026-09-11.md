- **Error-condition hardening** (section 24, "Fatal application error";
  section 18, "errors must be user-friendly"): `gui/main_window.py` now
  overrides `report_callback_exception`. Previously, an exception raised
  synchronously inside a Tk callback (bypassing the background-task error
  handling in `_start_background_task`, which already covered baseline
  creation and scanning) would hit Tk's default handler, which prints a
  traceback to stderr and otherwise does nothing. That's invisible once
  packaged with `--windowed` (no console — section 21), so the window
  would just look frozen with no explanation. It now logs the full
  traceback and shows the same user-friendly "The application encountered
  an unexpected error. Check the application log for details." message
  the spec's section 24 fatal-error state calls for, without crashing or
  leaving the window unusable.
  - `tests/test_gui_integration.py`: added
    `test_uncaught_callback_exception_shows_fatal_error_not_crash`,
    simulating an uncaught exception and asserting the dialog is shown,
    the window survives, and stays usable.
- **Packaging** (section 21, section 32): added `build_exe.bat`, running
  `pyinstaller --noconfirm --windowed --name SentinelLite app.py` (the
  one-folder form, not `--onefile`, per section 21's "reliability is more
  important than achieving a single executable").
  - **Build verification performed in this container** (Linux, since the
    container isn't Windows): ran the exact PyInstaller command from
    `build_exe.bat` directly against `app.py`. The build completed
    without missing-import or hidden-import errors (customtkinter,

    `README.md`'s Packaging section documents this explicitly. Build

## Notes / decisions

- The `report_callback_exception` fix is scoped narrowly: it only affects
  exceptions that reach Tk's dispatcher directly from a widget
  callback (e.g. a bug in a button's `command`). It does not change any
  existing background-thread error handling — `_start_background_task`
  already wraps baseline-creation and scan-worker exceptions and shows
  the same style of user-friendly dialog; that path was left untouched.
- No changes were made to `core/`, `storage/`, or `reports/` this run —
  Run 7 is QA and packaging, not a feature run, and section 37 directs
  implementing only the current run's objectives.
